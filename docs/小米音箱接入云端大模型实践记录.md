# 小米音箱接入本机云端大模型：实践过程记录

> 本文记录一次从选型到双音箱跑通的完整过程，便于他人复现。  
> 文中账号、密钥、设备 ID 等均已脱敏，请替换为你自己的值。

---

## 1. 目标

把家里的小米 / 小爱音箱，接到本机运行的桥接程序上，让音箱语音走**云端大模型 API**（OpenAI 兼容接口）回答，而不是只依赖原生小爱。

最终效果：

1. 对音箱说：「小爱同学，帮我……」或「请问……」
2. 本机桥接程序截获对话
3. 调用云端大模型
4. 音箱 TTS 播报回答

---

## 2. 设备与方案选型

### 2.1 实际设备

| 设备 | 型号 | 角色 |
|------|------|------|
| 小爱音箱 Pro | LX06 | 主音箱，体验最好 |
| 小爱音箱 Play 增强版 | L05C | 辅音箱，能问答，连续对话较弱 |

### 2.2 选定方案

**方案 A：免刷机 + [xiaogpt](https://github.com/yihong0618/xiaogpt)**

| 对比项 | 结论 |
|--------|------|
| 刷机深度接管（open-xiaoai） | 仅部分机型，风险高，本次不做 |
| 小爱开放平台自定义技能 | 偏正式技能，审核/HTTPS，不够自由 |
| 免刷机轮询对话记录（xiaogpt） | **采用**：不拆机，接任意 OpenAI 兼容 API |

大模型侧选择：**云端 API**（非本机 Ollama），只要兼容 OpenAI `chat/completions` 即可（DeepSeek、火山方舟、OpenAI 官方等）。

> 说明：Cursor 等 IDE Agent 不能直接当音箱后端；音箱只做语音入口，本机跑桥接 + 调 API。

## 3. 项目结构（本仓库）

在本机目录实现薄封装，配置统一走 `.env`：

```text
mi-ai/
  .env.example          # 配置模板（可提交）
  .env                  # 真实配置（勿提交）
  .gitignore
  requirements.txt
  logs/                 # 运行日志（勿提交；按天滚动，默认保留 7 天）
  scripts/
    install.ps1           # Windows 一键安装依赖
    install-service.ps1   # 注册任务计划 awam-mi-ai（登录自启）
    uninstall-service.ps1 # 注销任务计划
    service-start.ps1     # 立即启动保活
    service-stop.ps1      # 立即停止
    service-status.ps1    # 查看状态与日志路径
    watchdog.ps1          # 保活总控（任务计划实际执行）
    run-device.ps1         # 单音箱包装，输出写入日志
  mi_ai/
    settings.py         # 读取 ENV
    list_devices.py     # 列出音箱 DID
    login_mina.py       # 登录小米并写 ~/.mi.token
    run.py              # 启动 LX06 / L05C
    ensure_deps.py      # 精简 xiaogpt，仅保留 OpenAI 兼容 bot
    __main__.py         # python -m mi_ai ...
  docs/
    小米音箱接入云端大模型实践记录.md
```

设计要点：

- 两台音箱各跑一个进程，共用小米账号，**不同 `MI_DID` + 不同硬件参数**
- LX06：可 `stream`、可 mute 小爱
- L05C：**必须** `use_command=true`，且 **关闭** `stream`（查不到可靠播放状态）

## 4. 环境安装过程

### 4.1 遇到的坑：完整依赖装不动

直接 `pip install xiaogpt` / `xiaogpt[locked]` 时，会拉取 langchain、google-generativeai 等，在 Windows 上**依赖回退极慢甚至卡住**。

### 4.2 实际做法：虚拟环境 + 最小依赖

```powershell
cd <项目目录>
python -m venv .venv
.\scripts\install.ps1
# 或手动：
# .\.venv\Scripts\python.exe -m pip install xiaogpt==3.23 --no-deps
# 再装 miservice_fork、openai、aiohttp、rich、httpx、pyyaml、python-dotenv、requests 等
# 然后：python -m mi_ai.ensure_deps
```

`ensure_deps` 会把已安装的 `xiaogpt.bot` 入口精简为**只启用 chatgptapi**，避免导入未安装的 langchain / gemini 等模块。

## 5. 配置（`.env`）

从 `.env.example` 复制为 `.env`，填写（示例值为占位符）：

```env
# 小米账号
MI_USER=your_xiaomi_account
MI_PASS=your_password
MI_COOKIE=

# 云端大模型（OpenAI 兼容）
OPENAI_API_KEY=sk-xxxxxxxx
OPENAI_API_BASE=https://api.example.com/v1
OPENAI_MODEL=your-model-name

# 触发词
KEYWORDS=帮我,请
PROMPT=以下请用 300 字以内回答，请只回答文字不要带链接
VERBOSE=0

# LX06
LX06_DID=          # 登录后填写
LX06_HARDWARE=LX06
LX06_MUTE_XIAOAI=true
LX06_STREAM=true
LX06_USE_COMMAND=false

# L05C
L05C_DID=          # 登录后填写
L05C_HARDWARE=L05C
L05C_MUTE_XIAOAI=true
L05C_STREAM=false
L05C_USE_COMMAND=true
```

注意：

- `OPENAI_API_BASE` 一般以 `/v1` 结尾，**不要**写成 `/v1/chat/completions`
- `VERBOSE=1` 时 xiaogpt 可能把账号密钥打进日志，建议生产用 `0`

## 6. 小米登录与设备发现（需人机配合）

### 6.1 第一次登录失败

用账号密码调用 `micli` / 自写登录脚本时，常见：

- 错误码 **70016**「登录验证失败」
- 或返回 `code=0` 但带 `securityStatus=16` 与 `notificationUrl`

含义：密码可能正确，但需要**安全手机短信验证**，非交互环境无法代输验证码。

### 6.2 实际交互流程

1. 本机用 `.env` 中的 `MI_USER` / `MI_PASS` 发起登录  
2. 拿到身份验证链接，浏览器打开「小米账号安全验证」页  
3. **用户**点击「发送验证码」→ 手机收短信 → 填入提交  
4. 验证通过后，再次执行登录脚本  
5. 成功写入 `%USERPROFILE%\.mi.token`，并列出设备

命令（入口名是 `micli`，不是 `miservice`）：

```powershell
cd <项目目录>
.\.venv\Scripts\python.exe -m mi_ai.login_mina
# 或
$env:MI_USER="..."
$env:MI_PASS="..."
.\.venv\Scripts\micli.exe mina
```

### 6.3 列出设备结果（脱敏示例）

| 名称（示例） | hardware | miotDID（示例） |
|--------------|----------|-----------------|
| 小爱音箱 Pro | LX06 | `123456789` |
| Play 增强版 | L05C | `987654321` |

将 `miotDID` 填入 `.env` 的 `LX06_DID` / `L05C_DID`。

备选：浏览器登录 [account.xiaomi.com](https://account.xiaomi.com)，从 Cookie 取 `userId` + `passToken` 写入 `MI_COOKIE`。

## 8. 过程中踩过的坑与处理

| 现象 | 原因 | 处理 |
|------|------|------|
| `miservice.exe` 找不到 | 包入口名是 `micli` | 使用 `.\.venv\Scripts\micli.exe` |
| 登录 KeyError `userId` / 70016 | 风控要短信验证 | 打开 `notificationUrl` 完成验证后再登 |
| `pip install xiaogpt` 卡住 | 全量依赖回退 | venv + `--no-deps` + 最小依赖 + `ensure_deps` |
| L05C 识别到问题但崩溃，token 被删 | `use_command` 需 `xiaomiio`；失败时 miservice 会清空 token | 登录时同时登录 `micoapi` + `xiaomiio`；启动前检查并补齐 |
| L05C 已出模型回复却进程退出 | Windows 控制台 GBK 无法打印部分 Unicode | `stdout` 设为 UTF-8 / `errors=replace`；`PYTHONUTF8=1` |
| L05C 流式叠音 / 播报异常 | 无法可靠查播放状态 | `L05C_STREAM=false`，`L05C_USE_COMMAND=true` |

## 10. 日常使用速查

### 10.1 手动前台启动（调试）

```powershell
cd <项目目录>

# 重新登录（token 失效时）
.\.venv\Scripts\python.exe -m mi_ai.login_mina

# 只列设备
.\.venv\Scripts\python.exe -m mi_ai list

# 启动
.\.venv\Scripts\python.exe -m mi_ai run LX06
.\.venv\Scripts\python.exe -m mi_ai run L05C
```

停止：对应终端 `Ctrl+C`。

Token 默认路径：`%USERPROFILE%\.mi.token`（勿提交到 Git）。

### 10.2 Windows 任务计划与保活（推荐日常挂机）

一次安装（注册任务计划 **`awam-mi-ai`**，当前用户登录时自动启动）：

```powershell
cd <项目目录>
.\scripts\install-service.ps1
.\scripts\service-start.ps1
```

日常运维：

```powershell
.\scripts\service-status.ps1   # 状态 + 今日日志路径
.\scripts\service-start.ps1    # 立即启动（已在跑则跳过）
.\scripts\service-stop.ps1     # 立即停止总控与子进程
.\scripts\uninstall-service.ps1 # 注销任务计划并停止服务
```

相关 `.env` 项（见 `.env.example`）：

| 变量 | 含义 | 默认 |
|------|------|------|
| `MI_AI_DEVICES` | 保活哪些音箱（逗号分隔） | `LX06,L05C` |
| `MI_AI_RESTART_BASE_SEC` | 崩溃后首次重试等待（秒） | `5` |
| `MI_AI_RESTART_MAX_SEC` | 退避上限（秒） | `300` |
| `MI_AI_LOG_DIR` | 日志目录 | `logs` |
| `MI_AI_LOG_KEEP_DAYS` | 按天滚动保留天数 | `7` |

子进程若稳定运行不足约 60 秒就退出，会对该机型做指数退避，避免死循环狂启。

### 10.2.1 登录持久化（无人值守）

目标：日常用 `passToken` **静默续期**；只有小米强制短信验证时才需要人。

| 机制 | 说明 |
|------|------|
| 安全 token 存储 | 登录/401 失败时**不删除** `userId`/`passToken`，只清业务 `serviceToken` |
| 备份 | `data/mi.token.bak` |
| 种子 | 登录成功写入 `data/mi_pass_seed.json`，token 丢失时可重建 |
| 启动/定时探活 | `python -m mi_ai.auth_check`；watchdog 默认每 30 分钟跑一次 |
| 人工告警 | `logs/AUTH_REQUIRED.txt` + Windows 气泡通知；验证链接可能写入 `_auth_url.txt` |

首次或告警后请手动登录一次：

```powershell
.\.venv\Scripts\python.exe -m mi_ai.login_mina
.\scripts\service-stop.ps1
.\scripts\service-start.ps1
```

相关变量：`MI_AI_AUTH_CHECK_MINUTES`、`XIAOGPT_MI_TOKEN_PATH`、`MI_AI_PASS_SEED_PATH`（见 `.env.example`）。

### 10.3 日志路径（调试用）

默认目录：项目根下的 **`logs\`**（可用 `MI_AI_LOG_DIR` 改）。

| 文件 | 内容 |
|------|------|
| `logs\watchdog-YYYY-MM-DD.log` | 总控：启停、重启、退避、清理 |
| `logs\LX06-YYYY-MM-DD.log` | LX06 进程 stdout/stderr |
| `logs\L05C-YYYY-MM-DD.log` | L05C 进程 stdout/stderr |
| `logs\watchdog.pid` / `logs\<DEVICE>.pid` | 运行中 PID（停止后会删除） |
| `logs\AUTH_REQUIRED.txt` | 需要短信/人工验证时的告警（正常时不存在） |
| `data\mi.token` | 小米登录态（含 passToken；勿提交） |
| `data\mi_pass_seed.json` | passToken 种子，供误删后恢复 |

示例（按当天日期替换）：

```text
d:\Code\MI\mi-ai\logs\watchdog-2026-10-18.log
d:\Code\MI\mi-ai\logs\LX06-2026-10-18.log
d:\Code\MI\mi-ai\logs\L05C-2026-10-18.log
```

查看今日日志可用：

```powershell
Get-Content .\logs\watchdog-((Get-Date).ToString('yyyy-MM-dd')).log -Tail 50
Get-Content .\logs\LX06-((Get-Date).ToString('yyyy-MM-dd')).log -Tail 80
```

## 11. 风险与局限（分享时一并说明）

1. 依赖小米非官方接口（对话轮询 / MiIO），云端变更可能导致失效  
2. 账号密码、API Key、`.mi.token` 等同于凭证，勿上传公开仓库  
3. L05C 体验弱于 LX06（打断、连续对话）  
4. TTS 适合短口语，不适合播长代码  
5. 本方案不是「音箱直连 Cursor」，而是「音箱 → 本机桥接 → 云端 API」

## 12. 时间线摘要

1. 选型：免刷机 xiaogpt + 云端 OpenAI 兼容 API；设备 LX06 + L05C  
2. 本目录落地项目，配置进 `.env`  
3. 安装遇依赖地狱 → 改为最小依赖安装  
4. 用户填写账号与 API  
5. 登录触发短信验证 → 用户浏览器完成 → 拿到 DID 写入 ENV  
6. 先通 LX06  
7. 启 L05C：补 `xiaomiio`、修控制台编码后双机均通
